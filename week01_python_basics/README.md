## 二、每天怎么用这些文件（三步）

每个 `.py` 文件都是「可运行 + 带讲解 + 带练习」的三合一，用法固定：

1. **读**：从上往下读，注释里会写「应该输出什么」。
2. **跑**：按 `Ctrl+S` 保存 → 点 VS Code 右上角 ▶ 运行 → 看下方终端输出。
3. **练**：翻到文件下半部分的「动手练习」，自己写；写完再往下滑看参考答案。

> 参考答案在每个文件的最底部，**别提前滑**，先自己写错一遍比看答案学得快。

## 三、读不懂一行代码时怎么办：三级兜底

**先记住一条通用规则：带括号的是「动作」，不带括号的是「名字」。**

- 动作：`print(...)`、`len(...)`、`int(...)`、`replace(...)` —— 它们在"做一件事"
- 名字：`title`、`project_name`、`amount_str` —— 它们只是"装东西的盒子"

认得出这两类，一行代码就能读出大半意思。函数名到底是干什么的，属于**生词**，不是语法——查一次、见三次就记住了，不需要提前背单词表。

遇到看不懂的行，**不要卡住**，按顺序退：

| 情况 | 做什么 |
|------|--------|
| ① 注释看懂了 | 看代码怎么实现它 → 过 |
| ② 代码看不懂 | `Ctrl+S` 运行，对照注释里写的「应该输出什么」→ 对上了就过 |
| ③ 跑完还不明白 | 把这行连同上一行发我，逐词翻译 |

> **「看不懂但跑通了」是允许的，也是正常的。** 读代码是建立手感，不是逐字理解。
> 真正的理解发生在**写练习**的时候——写的时候会反复回去看上面的例子，那一刻才是学会的时刻。
> 判断「可以往下走」的标准不是能背出语法，而是**能看着一行代码说出它会输出什么**。

## 五、每天结束后把代码推到 GitHub（4 步，1 分钟）

1. VS Code 左侧点「源代码管理」图标（分叉那个）。
2. 在「更改」里点文件旁的 `+`，把要提交的文件暂存。
3. 上面的输入框写一句提交信息，例如：`feat: W1D1 Python 基础语法练习`。
4. 点 ✓ 提交，再点「同步更改」（↗）推送到 GitHub。
